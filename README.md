# Rayton — вёрстка сайта

Статическая вёрстка сайта по макету Figma «Rayton – new website»,
подготовленная под последующую натяжку на WordPress-тему.

Главная, СЕС, УЗЕ и ряд внутренних страниц перенесены из локального макета
Figma. Блог и Rayton TV используют готовые общие секции и оригинальный контент.
Остальные страницы сохраняют структуру прототипа Base44; подробности — ниже.

```

ses-industrial.html   Промислові СЕС

ses-consumption.html  СЕС для власного споживання
uze.html              УЗЕ
hybrid.html           Гібридні системи
autonomous.html       Автономні рішення
services.html         Послуги (8 якорных блоков)

projects.html         Проєкти          project.html — образец кейса

youtube.html          Rayton TV

assets/
  css/              fonts → base → layout → components → pages → motion → responsive
  js/main.js        шапка, мега-меню, бургер, аккордеоны, табы, счётчики,
                    движение при прокрутке
  fonts/            Montserrat 400/500/600/700 (latin, latin-ext, cyrillic, cyrillic-ext)
  img/              растровые изображения из макета
  icons/            SVG-иконки + sprite.svg (инлайнится в страницы)
```

Локальный просмотр:

```bash
python3 tools/serve.py 4173
```

Это тот же статический сервер, но с `Cache-Control: no-store` — правки CSS/JS
видны по обычному F5. Подойдёт и `python3 -m http.server 4173`, только тогда
придётся сбрасывать кеш вручную.

сайтов банков-партнёров.

## Адаптив

Брейкпоинты: **1440 / 1280 / 1024 / 768 / 480**.
Сначала сжимаются поля (`--gutter`: 120 → 64 → 40 → 32 → 24 → 16),
затем перестраиваются сетки, затем уменьшается типографика.

- ≤ 1024 — бургер-меню (панель на всю ширину, CTA переезжает внутрь меню);
  сетки 4 → 2 колонки; заголовок и подводка становятся друг под другом.
- ≤ 768 — карточки решений/проєктів/моделей в одну колонку; таблица
  порівняння УЗЕ превращается в стопку карточек (через `data-label`).
- ≤ 480 — всё в одну колонку, кнопки на всю ширину.

## Натяжка на WordPress

Вёрстка изначально разбита под шаблонные части:

| Блок в HTML | Файл темы |
|---|---|
| `<header class="site-header">` | `header.php` |
| `<footer class="site-footer">` | `footer.php` |
| `<!--@sprite-->` (инлайн SVG-спрайт) | `template-parts/sprite.php` |
| секции внутри `<main>` | `template-parts/section-*.php` |
| `index.html` | `front-page.php` |
| страницы решений, послуг, фінансування, про нас, контакти, FAQ, калькулятор | `page-*.php` или `page.php` + ACF |
| `projects.html` / `project.html` | `archive-project.php` / `single-project.php` |
| `blog.html` / `article.html` | `home.php` (или `archive.php`) / `single.php` |
| `youtube.html` | `page-youtube.php` + CPT «відео» |

Подключение стилей (порядок важен):

```php
$uri = get_template_directory_uri();
$ver = wp_get_theme()->get( 'Version' );

wp_enqueue_style( 'rayton-fonts',      "$uri/assets/css/fonts.css",      [], $ver );
wp_enqueue_style( 'rayton-base',       "$uri/assets/css/base.css",       [ 'rayton-fonts' ], $ver );
wp_enqueue_style( 'rayton-layout',     "$uri/assets/css/layout.css",     [ 'rayton-base' ], $ver );
wp_enqueue_style( 'rayton-components', "$uri/assets/css/components.css", [ 'rayton-base' ], $ver );
wp_enqueue_style( 'rayton-pages',      "$uri/assets/css/pages.css",      [ 'rayton-components' ], $ver );
wp_enqueue_style( 'rayton-motion',     "$uri/assets/css/motion.css",     [ 'rayton-pages' ], $ver );
wp_enqueue_style( 'rayton-responsive', "$uri/assets/css/responsive.css", [ 'rayton-motion' ], $ver );

wp_enqueue_script( 'rayton', "$uri/assets/js/main.js", [], $ver, true );
```

Что стоит вынести в поля/меню при интеграции:

- меню шапки и четыре колонки футера — `wp_nav_menu()` (жёлтая точка = класс `nav__link--dot`);
- контакты в футере, соцсети — опции темы / ACF Options;
- карточки решений, проєктів, моделей УЗЕ, статей — кастомные типы записей;
- калькулятор и форма заявки — обработчик на admin-ajax или REST + `wp_nonce`;
- таблица порівняння УЗЕ — репитер; кнопка «Показати всі» работает на классах
  `compare-table__extra` / `is-expanded` (см. `main.js`).

**Шапка.** Всегда `position: fixed`; класс `is-stuck` (ставится после 120 px
прокрутки, с гистерезисом) меняет только цвет фона. Раньше шапка была
`absolute` и переключалась на `fixed` на пороге — то есть уезжала вместе
с героем и телепортировалась обратно в кадр.

**Мега-меню.** Три раздела (СЕС, УЗЕ, Послуги) раскрывают панель во всю ширину.
Панель лежит внутри своего `<li>`, но позиционируется абсолютно относительно
`.site-header`, поэтому на десктопе это выпадашка, а в бургере — вложенный список.
В WP: `wp_nav_menu` с `walker`, который для пунктов с потомками выводит
`data-menu` на ссылке и панель `.mega` рядом.

Панель, затемнение и фон шапки открываются и закрываются одним движением
на `--dur`/`--ease`. Ничего не прячется через `display`/`hidden` — иначе
переход не проигрывается и часть жеста происходит за один кадр. При переходе
с одного раздела на другой «оправа» (фон шапки + затемнение) не трогается,
меняются только панели.

**Бургер (≤ 1024).** Панель раскрывается «шторкой» `grid-template-rows`
`0fr → 1fr` — на тех же `--dur`, что крестик бургера и цвет шапки, и
непрозрачно на всех кадрах (кроссфейд поверх фотографии героя давал призрак).
Для клипа нужна обёртка `.nav__inner`; на десктопе она `display: contents`
и на раскладку не влияет. Вложенные `.mega` внутри бургера раскрываются тем
же приёмом, синхронно с поворотом шеврона.

**Блок «Реалізовані об'єкти».** Табы переключают весь блок сразу: панели помечены
`data-tab-panel="0|1"`, один клик меняет и большую карточку, и боковой список.
Панель «Відео» использует фасад YouTube — `data-youtube="ID"` на карточке,
iframe создаётся только по клику (без загрузки плеера на старте).

**Счётчики.** `<span data-count="1000">` — число докручивается при попадании
в вьюпорт. Порог наблюдателя тот же, что у появления блоков, чтобы цифры
не стартовали позже плашки, на которой стоят. `prefers-reduced-motion`
уважается.

## Движение при прокрутке

Всё в `assets/css/motion.css` плюс один блок в `main.js`. Эффекта два, оба
намеренно сдержанные — крупные смещения сразу читаются как дешёвый приём.

**Параллакс.** Крупные фото едут медленнее контента: герой 56 px за экран
прокрутки (на внутренних 32 px), фото в «Про компанію» и полноэкранные
фоновые секции — ±26…30 px. Запас хода даёт «вылет» картинки за рамку
(`top: -6%; height: 112%`), поэтому по краям никогда не появляется пустота.

**Появление блоков.** Блоки поднимаются на 22 px и проявляются один раз
за 0.6 s. Единица показа — прямой ребёнок `.section > .container`: заголовок
с подводкой, сетка карточек, баннер. Так связанные вещи всегда едут вместе,
а не «заголовок поехал, а текст рядом стоит». Сетки карточек показывают
детей лесенкой; шаг задержки считается по пачке, которая вошла в экран,
а не по номеру ребёнка в разметке, — иначе вторая строка сетки ждала бы
задержку первой и въезжала рывком после паузы.

Целей в разметке нет: `main.js` размечает их сам обходом секций (`plan()`),
спускаясь внутрь там, где лежит сетка карточек, слой параллакса или блок
выше экрана (иначе к его низу анимация давно кончилась бы и нижняя половина
возникала готовой). Блок со своей прокруткой остаётся единицей целиком.
Вложенных целей не бывает — иначе ребёнок ехал бы 22 px внутри родителя,
который сам едет 22 px, а прозрачности перемножались бы.

Сам эффект — `@keyframes`, а не `transition`, и он снимается совсем, когда
отыграл (класс `is-done`). Это важно: `transition` на `[data-reveal]`
наследовался элементом навсегда и затирал собственный переход компонента —
у карточек внутри сеток ломался ховер.

Реализация — `IntersectionObserver` плюс один `requestAnimationFrame`-цикл,
общий для шапки и параллакса. Цикл пишет только CSS-переменную `--py`
(никакого layout, только composited transform; чтения геометрии батчатся
перед записями).

Полноэкранные секции с фото используют слой `<div class="section-bg">`
с обычным `<img>` вместо `background` у самой секции — картинку так можно
двигать, а браузеру проще её композитить.

Почему не CSS scroll-driven animations (`animation-timeline`): `view()`
привязывается к ближайшему scroll-контейнеру, а `overflow: hidden` стоит
и на героях, и на фоновых секциях — таймлайн цеплялся за них и стоял мёртво.
JS-путь ведёт себя одинаково во всех браузерах.

При `prefers-reduced-motion: reduce` движения нет совсем — глушатся не
только параллакс и появления, но и всё, что человек запускает руками:
меню, затемнение, аккордеон, ховеры, плавная прокрутка по якорям.
При отключённом JS страница просто статична.

JS не использует зависимостей и безопасно подключается с `defer`.
Разметка семантическая: заголовки по иерархии, `aria-expanded` на аккордеонах
и бургере, `aria-current` на активном пункте меню, скрытые подписи для скринридеров.

## Что взято из макета как есть, а что пришлось дописать

Разметка повторяет макет; часть контента в Figma осталась незаполненной —
там подставлен осмысленный текст. Это стоит проверить перед публикацией:

1. **«Як ми працюємо»** — в макете все карточки 01–04 продублированы как
   «01 Аудит», заполнена только 05. Проставил 01 Аудит → 02 Проєкт →
   03 Обладнання → 04 Монтаж → 05 Запуск.
2. **«Для яких бізнесів підходить СЕС»** — в макете все восемь плашек
   «Виробництва». Проставил разные типы бизнеса.
3. **Меню футера** — в макете все ссылки «СЕС для бізнесу». Проставил
   реальные разделы; контакты — плейсхолдеры (телефон, e-mail, адрес).
4. **Вторая кнопка в hero** — в макете обе называются «Розрахувати проєкт».
   Вторая переименована в «Отримати консультацію».
5. **Таблица порівняння УЗЕ** — в макете все 14 строк одинаковые
   («RESS 125-261»). Заполнил рядом моделей.
6. **«Реалізовані об'єкти» на главной** — список справа в макете содержит
   один и тот же заголовок; проставлены разные.

**Заголовки hero — белые на всех страницах.** В экспортированном `.fig` на главной
и на СЕС они были тёмными (`#181818`), но по присланному референсу и по логике
(тёмный текст на тёмном фото не читается) везде поставлен белый.

**Градиентное размытие hero.** В макете стоит `PROGRESSIVE` blur: резко в точке
(57%, 29%), полное размытие 44.5 px в точке (20%, 59%) — то есть чётко справа
и мягко влево. В CSS градиентного блюра нет, поэтому лежат два слоя картинки:
резкий и размытый, второй проявляется маской вдоль той же оси
(`linear-gradient(247.2deg, transparent 40.7%, #000 76.4%)`).

**Подчёркнутая часть заголовка — серая.** В макете у выделенных жёлтым слов
свой цвет: `#5a5852` на светлом фоне и `#cccccc` на тёмном. Это зашито
в `.mark` / `.mark--dark`; вариант `.mark--plain` (только полоса) — для счётчиков.

## Служебные скрипты

```bash
node tools/build-partials.js   # инлайнит sprite.svg и футер во все страницы
node tools/compare.js index.html home 7400   # скриншот вёрстки + рендера макета
python3 tools/sbs.py <ref.png> <mine.png> <outdir> 760   # склейка side-by-side
```

`tools/build-partials.js` нужно запускать после правки `assets/icons/sprite.svg`,
шапки или футера в `index.html` — они синхронизируются во все страницы из главной.
Флаг `--bump` дополнительно обновляет `?v=` у CSS/JS (аналог `$ver`
в `wp_enqueue_style`); без флага версия не трогается, чтобы не шуметь в диффах.

В `tools/figma/` лежат скрипты, которыми макет разбирался в данные: декодер
бинарного `.fig` (kiwi + zstd), резолвер компонентов, экспорт геометрии и иконок
и справочный HTML-рендер макета для попиксельной сверки. Понадобятся, если макет
обновится — см. `tools/figma/README.md`. Сам справочный рендер в репозитории не
хранится (он тянет ~290 МБ исходных изображений), но воспроизводится за пару команд.

### Постепенное подключение переводов

`assets/js/locales/header.js` содержит словари `uk`, `ru`, `en` (UA — подпись
кнопки для стандартного кода `uk`). `assets/js/i18n.js` применяет ключи
`data-i18n="namespace.key"` и `data-i18n-aria="namespace.key"`, сохраняет язык
в localStorage и поддерживает `?lang=uk|ru|en` для прямого открытия.

Для нового раздела добавьте одинаковые ключи во все три словаря и разметьте
переводимые элементы атрибутами. Тексты вставляются безопасно через textContent.
API: `RaytonI18n.t(key)`, `setLocale(locale)`, `getLocale()`, `apply(root)`;
событие `rayton:localechange` содержит `detail.locale`. Отсутствующие переводы
берутся из украинского словаря. Пока переведён только хедер; язык документа
остаётся `uk`, а переведённые элементы получают собственный `lang`. Полные
переводы страниц, метаданные и языковые URL необходимо подключать вместе
с переводом контента, до публикации полноценной многоязычной версии.
